These are properties of the sources, not defects. `unknown_roles` is dominated by DIDI,
whose prompts carry no semantics, and by flowchartseg, which has one node class;
`nodes_without_text` by the same two. They are counted here so that a later phase
cannot quietly train on them and report the result as role classification.

## What this does and does not check

| Checked | Not checked |
| :--- | :--- |
| The file matches `schemas/ir.schema.json` | Whether a shape label is *correct* - see `reports/annotator_agreement.md` |
| Every edge endpoint is a node in the same diagram | Whether the edge should exist at all |
| Every box lies within its image, with 1% slack | Whether the box is tight around the ink |
| Every open-ended edge appears in `unresolved_edges` | Whether it *should* have been resolvable |
| `crossed_out` and `low_conf_text` name real elements | Whether the transcription is right |
| `meta.image` exists on disk | Whether it is the right image |
| Roles belong to the diagram type | Whether the diagram type is right |

The right-hand column is not a gap to be closed here. Those are questions about
correctness rather than consistency, and they are answered by Phase 2.2.4's agreement
measurement and by human review, not by a validator.
