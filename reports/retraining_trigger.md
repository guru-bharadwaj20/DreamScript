# Phase 15.8 - the retraining trigger

Generated by `python -m src.mlops.retrain`.

**A trigger that only ever says 'retrain' is a cron job.** This one is allowed to refuse, and the refusals are the part worth having: this project has measured three cases where retraining is the wrong move, and a rule that ignored them would recommend the thing that already failed.

They prove the detector works; they are not evidence that the input has moved. `--against <batch>` is what scores real traffic | no |
| `confidence` | 15.6 `reports/prediction_monitoring.json` | the spike arm is the degradation control, not production traffic; a real batch is scored with `python -m src.mlops.monitor --against <batch>` | no |

**Neither 15.5's nor 15.6's alarms fire this trigger from their reports**, and that is deliberate rather than an oversight: the shifts in those reports are each row's own calibration arms - a new diagram type, a new capture device, 14.5's degradations - which exist to prove the detector works. They are not observed traffic. Firing a retrain on them would be firing on the calibration set. Real traffic is scored with `--against`.

## Where retraining is already known not to help

| component | pull this instead | the measurement that says so |
| :--- | :--- | :--- |
| ocr | crop selection, not the reader | S3: more epochs +0.0089 CER, stronger augmentation +0.0040, retrain-on-reselection +0.0067 - three retrains, all worse. The oracle over the crops already in hand is 0.0737 against the learned ranker's 0.1890, so the remaining distance is selection |
| generation | 12.1.6's emitter, not the model | 12.3.3 grades against the reference programs, so every point the emitter gains raises the bar too; the model is at 0.7037 under a 0.784 ceiling and cannot pass by imitating an emitter that is itself failing 35 of 162 |

The correction threshold is **500** usable corrections. Set against the corpus rather than picked: S3 trains on 8,896 label crops, so 500 corrected labels is about 5.6% new signal on exactly the examples a user cared enough to fix. Below that the run costs more than it can move.
